# Первый запуск Freeflare Desk на Cloudflare

Это порядок для **новой установки с пустыми D1** и отдельной Админушкой. Если базы уже существуют, используйте [обновление БД](database-upgrade.md) и [настройку Админушки](manager-bot.md). Старый путь с управляющими командами сервисного бота в General сохранён [в архиве](legacy-setup.md).

## Мастер первого запуска (Windows)

Откройте PowerShell в папке проекта. Нужны Windows, Node.js 22.13+ с npm, аккаунт Cloudflare, новая Админушка из BotFather и группа с включёнными темами. Добавьте Админушку администратором группы с правами управлять темами и закреплять сообщения.

```powershell
npm run setup
```

Мастер проведёт по шагам:

1. Предложит язык мастера: **1 — Русский**, **2 — English**. Выбор появляется до входа в сервисы и действует на подсказки, меню, ошибки и подключение Telegram Serverless.
2. Предложит имя новой установки или выбор сохранённой. При необходимости откроет вход в Cloudflare в браузере; единственный аккаунт выберет сам, несколько покажет списком.
3. Проверит токен Админушки и её права. Попросит отправить `/setup@имя_бота` в General от своего аккаунта и подтвердить найденную группу. ID вручную копировать не нужно. Если команда ещё не пришла или права не выданы, можно повторить проверку на месте.
4. Попробует определить адрес `workers.dev`. Если это недоступно, покажет, где найти субдомен. Даст точный hostname и ссылку для создания Turnstile Managed: скопируйте site key и secret key из одного виджета. `support_verify` уже задаётся кодом страницы проверки, в панели виджета его вводить не требуется.
5. Предложит часовой пояс компьютера и язык алертов; по умолчанию — выбранный язык мастера. Язык алертов задаётся отдельно: English, Русский, Español или 简体中文. Перед созданием покажет ресурсы и попросит ввести **СОЗДАТЬ** в русском режиме или **CREATE** в английском.
6. Создаст две D1, применит миграции, сохранит секреты и зашифрованные копии генерируемых ключей, опубликует оба Worker в нужном порядке. Отдельно запросит Cloudflare API token для аналитики с правом чтения D1 — [требования монитора](monitoring.md#подготовка).
7. Проверит HTTP-маршрут Админушки, связь монитора с основным Worker и чтение обеих БД, затем подключит webhook. Входящие обновления Telegram сохраняются.
8. Предложит подключить `/status` в алерт-боте на Telegram Serverless сейчас или позже.

Токены вводятся в скрытые запросы мастера/CLI. Они не записываются в исходники или файл состояния. Неверные обычные значения можно исправить без перезапуска. При миграциях Wrangler может запросить дополнительное подтверждение.

Сообщения внешних Wrangler и Telegram CLI выводятся на их собственном языке. Названия групп, аккаунтов, пути и команды сохраняются как есть.

### Если установка прервалась

Запустите `npm run setup` и выберите сохранённую установку либо выполните показанную мастером команду, например:

```powershell
node scripts/bootstrap.mjs support-myteam-2026
```

Повторный запуск снова начинается с выбора языка; его можно сменить без повторного выполнения завершённых этапов или изменения языка существующих алертов. Повторный запуск проверяет аккаунт, бота и UUID баз. Завершённые шаги пропускаются, только если их код, конфигурация или набор миграций не изменились. Потерянные ответы Cloudflare и неоконченные шаги проверяются повторно. Уже завершённая новая установка не публикуется повторно: мастер предлагает только подключение статуса.

Создаются отдельные `wrangler.bootstrap.ИМЯ.toml`, `wrangler.bootstrap.ИМЯ.first.toml`, `monitor/wrangler.bootstrap.ИМЯ.toml` и `.bootstrap-state-ИМЯ.json`; они исключены из Git. Мастер обновляет созданные им конфигурации при изменении шаблонов, но останавливается, если файл менялся вручную. Состояния прежней версии поддерживаются; старые изменившиеся конфигурации без сохранённой контрольной суммы требуют ручной сверки.

Сохраните файл состояния, сгенерированные TOML и каталог резервных копий, который покажет мастер. DPAPI-копии ключей открываются только той же учётной записью Windows на том же компьютере. Если ключ уже есть в Cloudflare, а копия потеряна, мастер остановится, чтобы не заменить ключ шифрования.

Для дальнейших публикаций используйте сгенерированные файлы через `--config`: обычные `wrangler.toml` в репозитории относятся к другой установке. Мастер предназначен для первого запуска и его продолжения; обновление работающего проекта выполняется отдельно.

### Статус в алерт-боте на Telegram Serverless

В **Админушка → Алерты** подключите отдельного алерт-бота и выберите адрес обычных уведомлений. В BotFather включите Serverless **для этого же алерт-бота** и получите CLI Access token. Выберите подключение статуса в конце мастера либо выполните:

```powershell
node scripts/bootstrap.mjs support-myteam-2026 --status-bot
```

Режим использует уже сохранённую установку и не требует повторно вводить токен Админушки. Мастер проверит бота и webhook, создаст таблицы Telegram и отдельный ключ чтения статуса, подключит монитор и обработчики. Он принимает пустое приложение Serverless или продолжает приложение, которое сам начал устанавливать. Чужая программа или внешний webhook автоматически не заменяются.

Проект Telegram находится в `.bootstrap-serverless/ИМЯ/`. В нём свои ID администратора, группы и бота, URL монитора, часовой пояс и `STATUS_LOCALE`: выбранный язык алертов применяется также к экрану статуса, кнопкам и ошибкам. Его CLI-вход независим от `alert-serverless/` основной установки. Каталог исключён из Git; `.tgcloud/` внутри него управляется только CLI.

После подключения `/status@имя_алерт_бота` работает для главного администратора в личке и исходной группе, с ответом в тот же топик. Обычные алерты отправляет Cloudflare. Независимого запуска по расписанию нет. Сразу после установки статус может предупреждать, что Cron ещё не собрал первые данные.

В конце откройте личку Админушки и отправьте `/start`. Подключите первый сервис через **Управление ботами поддержки → Добавить сервисного бота** и выполните контрольный обмен с тестовым аккаунтом. Проверка мастера подтверждает доступность компонентов; доставку настоящего пользовательского сообщения проверяет этот обмен.

Справка на обоих языках без входа в сервисы: `node scripts/bootstrap.mjs --help`. Ниже — ручной порядок для диагностики и нестандартных развёртываний.

Все команды выполняются в PowerShell из папки проекта. Нужны Node.js 22.13+ (для `node:sqlite`), доступ к Cloudflare и Telegram. Мастер использует `wrangler@4.149.0` и Telegram CLI `0.2.0`. Токены и ключи вводите только в локальные скрытые запросы Wrangler/скриптов, не добавляйте их в Git. `deploy` публикует локальный код непосредственно в Cloudflare; `git push` сам по себе Worker не обновляет.

## 1. Подготовьте Telegram и узнайте ID

1. Создайте **отдельного управляющего бота** через [@BotFather](https://t.me/BotFather). Создайте группу с включёнными темами и добавьте Админушку администратором с правами отправлять и закреплять сообщения и управлять темами.
2. От своего личного аккаунта отправьте `/setup` в General. До установки webhook выполните `node scripts/telegram-setup.mjs` и введите токен Админушки. Из результата возьмите `UserId` для `ADMIN_IDS` и `GroupId` для `SUPPORT_GROUP_ID`. Проверьте `IsForum = True` и пустой `SentAsChat`. Если у бота уже есть webhook, сначала выясните, где он работает; скрипт его не отключает.
3. Сервисного бота можно создать сейчас, но подключать его к Worker вручную не нужно: после запуска это сделает мастер Админушки. Ему понадобятся права отправлять сообщения и управлять темами в выбранной группе.

## 2. Подготовьте Cloudflare и конфигурацию

```powershell
npx.cmd --yes wrangler@4.149.0 login
npx.cmd --yes wrangler@4.149.0 whoami
npx.cmd --yes wrangler@4.149.0 d1 create telegram-support --config wrangler.toml
npx.cmd --yes wrangler@4.149.0 d1 create support-monitor --config monitor/wrangler.toml
```

Запишите два разных `database_id` в соответствующие `[[d1_databases]]`. Создайте в Cloudflare Turnstile виджет **Managed** с разрешённым hostname основного Worker. Action `support_verify` уже задаётся кодом страницы проверки. В `wrangler.toml` задайте свои `ADMIN_IDS` (ровно один ID), `SUPPORT_GROUP_ID`, `MANAGER_BOT_USERNAME` без `@`, `PUBLIC_BASE_URL` и публичный `TURNSTILE_SITE_KEY`. Его секретный ключ вводится только в Wrangler на следующем шаге. `BOT_REGISTRY = "[]"` для нового развёртывания оставьте пустым: сервисы добавляются через Админушку и D1. Проверьте, что пять `ratelimits.namespace_id` не заняты другими Worker аккаунта. В `monitor/wrangler.toml` задайте `CF_ACCOUNT_ID` из `whoami`; начальные `ALERT_CHAT_ID`/`ALERT_THREAD_ID` не заменяют подключение через меню **Алерты**. Проверьте также имена обоих Worker и service bindings в файлах. Не используйте ID и адреса, оставшиеся от чужой установки.

Проверьте схему локально, затем примените все ещё отсутствующие миграции из `migrations/` и `monitor/migrations/` к **нужным** облачным базам:

```powershell
node scripts/validate-d1-migrations.mjs
npx.cmd --yes wrangler@4.149.0 d1 migrations apply telegram-support --remote --config wrangler.toml
npx.cmd --yes wrangler@4.149.0 d1 migrations apply support-monitor --remote --config monitor/wrangler.toml
```

Перед подтверждением Wrangler сверьте имя и UUID каждой базы. Если она не пустая, остановитесь и перейдите к [инструкции обновления](database-upgrade.md).

## 3. Сохраните секреты и проверьте сборку

Через `wrangler secret put` для основного Worker установите `MANAGER_BOT_TOKEN`, отдельный случайный `MANAGER_WEBHOOK_SECRET` и `TURNSTILE_SECRET_KEY`. Webhook secret не выдаётся BotFather: сгенерируйте 32 случайных байта, например `node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"`, и сохраните строку для шага 5. Не путайте её с токеном бота.

```powershell
npx.cmd --yes wrangler@4.149.0 secret put MANAGER_BOT_TOKEN --config wrangler.toml
npx.cmd --yes wrangler@4.149.0 secret put MANAGER_WEBHOOK_SECRET --config wrangler.toml
npx.cmd --yes wrangler@4.149.0 secret put TURNSTILE_SECRET_KEY --config wrangler.toml
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\initialize-bot-registry-key.ps1
```

Для монитора создайте Cloudflare API token с доступом к аналитике Workers и чтению D1 (подробности прав — в [руководстве мониторинга](monitoring.md)), сохраните его как `CF_ANALYTICS_TOKEN`. Ключ шифрования алерт-бота нужен для подключения через Админушку:

```powershell
npx.cmd --yes wrangler@4.149.0 secret put CF_ANALYTICS_TOKEN --config monitor/wrangler.toml
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\initialize-alert-config-key.ps1
npm.cmd test
node scripts/validate-wrangler.mjs
```

Сохраните резервные копии ключей шифрования, созданные скриптами, вне Git. Число тестов зависит от версии кода. Локальные проверки не подтверждают действительные права Telegram и Cloudflare.

## 4. Опубликуйте оба Worker

Для **самого первого** deploy временно закомментируйте в конце `wrangler.toml` три блока `[[services]]`: `STORAGE_MONITOR`, `USER_ACCESS_ALERTS`, `ALERT_SETTINGS`. Затем выполните по очереди:

```powershell
npx.cmd --yes wrangler@4.149.0 deploy --config wrangler.toml
npx.cmd --yes wrangler@4.149.0 deploy --config monitor/wrangler.toml
```

Верните все три блока `[[services]]` и снова опубликуйте основной Worker:

```powershell
npx.cmd --yes wrangler@4.149.0 deploy --config wrangler.toml
```

Эта последовательность нужна из-за взаимных service bindings. После неё основной Worker должен отвечать по `PUBLIC_BASE_URL`. При дальнейших выпусках применяйте лишь недостающие миграции и публикуйте Worker, код или конфигурация которого менялись.

## 5. Подключите Админушку и первый сервис

```powershell
node scripts/telegram-webhook.mjs manager
```

Введите токен Админушки и **тот же** `MANAGER_WEBHOOK_SECRET`, который сохранили в Cloudflare. Скрипт регистрирует `/tg/manager` без сброса ожидающих обновлений. Откройте личку Админушки и отправьте `/start`: это проверяет маршрут webhook. Добавьте Админушку администратором каждой будущей группы поддержки.

Личный интерфейс Админушки и новые сервисы по умолчанию открываются на английском. Чтобы названия кнопок совпадали с этим руководством, сначала выберите **🌐 Interface language → 🇷🇺 Русский**. Оператор меняет свой язык через эту кнопку в главном меню; главный администратор задаёт язык конкретного сервиса через **⚙️ Настройки сервиса → 🌐 Сменить язык**. Доступны English, Русский, Español и 简体中文.

В личке откройте **Управление ботами поддержки → Добавить сервисного бота**. Мастер поможет выбрать или подключить группу, добавить сервисного бота, настроить webhook и проверить реакции в обе стороны; после успешной проверки реакции включаются автоматически. Для нового бота можно скопировать приветствие и подтверждение получения обращения с другого сервиса. Проверьте карточку готовности и **Контрольный обмен**. [Подробный порядок подключения](manager-bot.md#подключение-сервиса-и-группы).

Для проверки с отдельного тестового аккаунта отправьте сообщение сервисному боту, ответьте из созданной темы и убедитесь в доставке обратно. Закройте тему через Админушку и проверьте возобновление новым сообщением. Операторов добавляйте в **Операторы**; каждый должен отправить `/start` Админушке для личных уведомлений. В **План и хранилище** проверьте тариф и измерения D1. Алерт-бот подключается отдельно через **Алерты** с выбором одного маршрута: топик группы или личные чаты администратора и отмеченных операторов. [Настройка алертов](manager-bot.md#алерт-бот).

При неполадках смотрите `npx.cmd --yes wrangler@4.149.0 tail --config wrangler.toml` и аналогичную команду с `monitor/wrangler.toml`; не удаляйте D1 или ожидающие обновления Telegram ради диагностики.
