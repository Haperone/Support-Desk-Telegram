# Статус алерт-бота на Telegram Serverless

[Все инструкции](../README.md) · [English](../en/alert-status.md)

Этот необязательный компонент добавляет `/status`, `/health`, `/start` и кнопку
обновления тому же боту, который отправляет алерты Cloudflare. Сбор показателей и
отправка уведомлений остаются на Cloudflare; Telegram обрабатывает запросы статуса.
Имя бота, ID администратора и группы выбираются для вашей установки.

## Подключение через мастер

Сначала подключите отдельного алерт-бота в меню **Алерты** управляющего бота и выберите
маршрут обычных уведомлений. Включите Serverless для этого же алерт-бота в BotFather
и получите CLI Access. В конце `npm run setup` выберите подключение статуса или
из корня проекта выполните команду для сохранённой установки:

```powershell
node scripts/bootstrap.mjs support-myteam-2026 --status-bot
```

Замените имя установки своим. Мастер создаёт отдельную исключённую из Git папку
`.bootstrap-serverless/ИМЯ/`, помогает войти через CLI, проверяет личность бота,
настраивает таблицы, ключ чтения статуса и обработчики. Чужую программу или webhook
другого сервиса он не заменяет. Управляющий бот и алерт-бот должны быть разными.
Подробности и продолжение прерванной настройки — в [первом запуске](first-launch.md).

## Использование

Главный администратор отправляет `/status` в личке алерт-бота или
`/status@имя_алерт_бота` в разрешённой группе. Ответ приходит в исходный топик.
Команды, адресованные другому боту, игнорируются. Обычные участники группы не получают
доступ к статусу только за счёт членства в ней.

Экран показывает доступность приложения и баз, свежесть проверок, инциденты, маршрут
алертов и последнюю подтверждённую отправку. Подтверждение означает принятие сообщения
Telegram, а не его прочтение человеком. Проверка не заменяет контрольный обмен
реальным сообщением между тестовым клиентом и оператором.

Если Cloudflare недоступен, показывается сохранённый результат с возрастом и
предупреждением. Запросы в течение 30 секунд используют кэш, в том числе результат
неудачной проверки. Сразу после установки Cron ещё может не собрать первый снимок.

## Настройки и ограничения

Публичный шаблон `alert-serverless/tgcloud/lib/settings.js` никому не разрешает доступ.
Мастер создаёт собственные ID администратора, группы и бота, часовой пояс и язык
`en`, `ru`, `es` или `zh` в отдельном рабочем каталоге. Для ручной настройки используйте
отдельную копию проекта; её настройки и CLI-сессия не должны попадать в публичный Git.
Каталог `.tgcloud` обслуживается только CLI: вручную читать или менять его не нужно.

`STATUS_READ_TOKEN` — отдельный секрет монитора; это не Telegram bot token.
Endpoint `GET /health/status` требует этот ключ: 200 означает здоровый результат,
503 — ухудшение состояния, 401 — отсутствие нужного доступа, 404 — ненастроенный компонент.
В ответ не включаются токены и тексты переписки. Ключ для запроса хранится в приватной
базе Telegram. Обычный маршрут уведомлений по-прежнему выбирается в управляющем боте.

Независимого запуска по расписанию и резервного канала уведомлений здесь нет:
статус проверяется по запросу, Telegram остаётся общей зависимостью. Для проверки
кода выполните `npm test` из корня; тесты не требуют рабочих ключей.

[Документация платформы](https://core.telegram.org/bots/serverless).
