# Проверка и включение реакций

Главный администратор проверяет каждого бота отдельно при подключении. Пользователям никаких новых кнопок не добавляется. Тест не создаёт обращения, не запускает приветствие или капчу. После успешной проверки обоих направлений реакции включаются автоматически.

## Проверка через Telegram

1. В личке Админушки открой карточку сервиса → **«🧪 Проверить реакции»**. Для нового бота эта кнопка есть сразу в конце мастера подключения.
2. Админушка покажет ссылку на сервисного бота и ход проверки.
3. Нажми **«Открыть бота для проверки»**, затем **«Старт»** в его личном чате. Бот подготовит два тестовых сообщения: в личке и в General. Используй свой аккаунт главного администратора.
4. Перейди по кнопке **«Тест в General»**. На самом тестовом сообщении поставь **👍**, дождись обновления текста, замени реакцию на **👀**, снова дождись обновления и затем сними свою реакцию. Это проверяет направление **«Поддержка → пользователь»**. Бот последовательно переносит эти изменения в личку.
5. На тестовом сообщении **в личке** выполни ту же последовательность по подсказкам. Это отдельная проверка **«Пользователь → поддержка»**. Изменения должны переноситься в General.
6. Вернись в Админушку → карточка сервиса → **«Реакции»** и нажми **«Обновить результат»**. После проверки обоих направлений они включатся сами. Проверь реакцию на обычном сообщении в обращении.

Не ставь реакции на исходную панель настроек: нужны именно два сообщения с заголовком **«Проверка реакций»**. После каждого действия дождись следующей подсказки — быстрое проставление всех реакций подряд не заменяет последовательную проверку.

### Если прогресс не меняется

Нажми **«Обновить результат»**. Если реакция уже поставлена, а шаг не засчитан, бот ещё не получил соответствующее событие Telegram или Telegram не подтвердил перенос. Ошибка переноса показывается в результате; убери свою реакцию и повтори указанный шаг. При необходимости проверь права администратора у бота в группе и доступность 👍 и 👀 в настройках реакций группы.

Telegram требует отдельно подписаться на `message_reaction` и указывает необходимость прав администратора в чате. Получение событий из обычной лички не гарантируется этим описанием. Поэтому проверка не предполагает, что оба направления обязательно будут доступны. [Telegram Bot API: Update](https://core.telegram.org/bots/api#update), [setMessageReaction](https://core.telegram.org/bots/api#setmessagereaction).

Можно закрыть проверку и вручную включить **только успешно проверенное направление** в настройках Админушки. Отсутствие события не считается успешной проверкой. Ссылка действует 20 минут; после истечения срока оставшиеся направления показываются как неподтверждённые. Новую проверку начинай из карточки сервиса.

Если подготовка тестовых сообщений прервалась, закрой проверку и начни новую. Старые кнопки и реакции на старых тестовых сообщениях не могут подтвердить новую проверку. Повторное открытие действующей ссылки показывает уже созданные сообщения.

Повторная проверка сама не отключает ранее включённое направление. Если оно перестало работать, выключи его в настройках на время проверки. Для отключения не требуется проходить тест. Переключатели направлений находятся в личке Админушки, в настройках выбранного сервиса.

В обычной переписке поддерживаются все **73 стандартные реакции Telegram** из [ReactionTypeEmoji](https://core.telegram.org/bots/api#reactiontypeemoji) на 14 сентября 2026, включая `🔥`, `🥰`, `🎉`, `💯` и `🤝`. Варианты вроде `❤️` и `❤` считаются одной реакцией. Переносятся установка, замена и снятие в обоих направлениях. Бот ставит одну реакцию на сообщение: если Telegram прислал несколько, выбирается последняя стандартная. В целевом чате она должна быть разрешена настройками реакций.

Custom emoji, платные реакции и emoji вне стандартного каталога (например, `✅`) не переносятся. Если ими заменить стандартную реакцию, её прежнее зеркало снимается. Реакции, поставленные самим ботом, повторно не зеркалируются. Проверка на одном боте не подтверждает остальные. Последовательность `👍 → 👀 → снять` проверяет механизм переноса и не ограничивает доступный набор.

Расширение набора до всех стандартных реакций не требует миграции базы или повторной проверки уже подтверждённых направлений; достаточно публикации Worker.

## Установка обновления 0030

Для уже установленной версии с миграцией 0029 нужны резервная копия, миграция **0030** и один deploy основного Worker. Монитор и секреты менять не требуется. Старые миграции и начальную схему не редактируй.

В PowerShell из папки проекта выполняй блоки по очереди. Если команда завершилась ошибкой, следующий блок не запускай.

```powershell
$reactionBackup = Join-Path $env:TEMP ('telegram-support-before-0030-' + (Get-Date -Format 'yyyyMMdd-HHmmss') + '.sql')
npx.cmd --yes wrangler@4.128.0 d1 export telegram-support --remote --config wrangler.toml --output "$reactionBackup"
if ($LASTEXITCODE -ne 0) { throw 'Резервная копия не создана. Остановитесь здесь.' }
Get-Item -LiteralPath $reactionBackup | Select-Object FullName, Length
```

```powershell
npx.cmd --yes wrangler@4.128.0 d1 migrations apply telegram-support --remote --config wrangler.toml
if ($LASTEXITCODE -ne 0) { throw 'Миграции не завершены. Deploy пока не выполняйте.' }
```

```powershell
npx.cmd --yes wrangler@4.128.0 deploy --config wrangler.toml
if ($LASTEXITCODE -ne 0) { throw 'Deploy не завершён.' }
```

Wrangler применяет все отсутствующие миграции по порядку одной командой. Если обновление подключения ботов 0029 ещё не устанавливалось, дополнительно выполни однократную настройку ключа из [инструкции подключения ботов](bot-registration.md) перед deploy. Если не установлены уведомления 0028, сначала обнови монитор по той же инструкции.

В текущей версии открой **Админушка → нужный сервис → Реакции** и пройди проверку выше. Править SQL вручную для включения реакций больше не нужно.
