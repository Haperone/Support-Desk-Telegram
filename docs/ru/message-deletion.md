# Удаление сообщений оператора

В теме поддержки ответьте **на своё отправленное сообщение** командой
`/delete@ИмяСервисногоБота`. Обычный `/delete` также работает в теме этого сервиса.
Команда не пересылается клиенту. Для альбома удаляется только выбранный элемент.

Бот сначала удаляет подтверждённую копию у клиента, затем оригинал в теме.
Если удаление у клиента не подтверждено, оригинал остаётся. При частичном
результате проверьте тему и повторите команду, если оригинал ещё виден.
Сервисному боту необходимо право **Delete Messages / Удаление сообщений** в
группе поддержки для удаления сообщений оператора.

Предупреждение об обычном удалении показывается в закреплённой панели новой
и повторно открытой темы, карточках обращения и пользователя, уведомлении со
ссылкой на тему, списке обращений и справке. Оно переведено на ru/en/es/zh.
Telegram не сообщает боту о просмотре темы: при каждом заходе доступна
закреплённая подсказка, но отдельное событие для всплывающего сообщения отсутствует.

## Ограничения Telegram

- Удаление доступно для сообщений младше 48 часов.
- Сообщение с игральной костью в личном чате можно удалить только спустя
  24 часа после отправки, при сохранении общего ограничения 48 часов.
- Обычное удаление через меню Telegram не синхронизируется с клиентом.
- Ответы 429, ошибки сервера, таймауты и некорректный JSON не подтверждают удаление.
  Успехом считается успешный ответ API либо определённый отказ 400
  `message to delete not found` для уже известного идентификатора.

Источник: [Telegram Bot API — deleteMessage](https://core.telegram.org/bots/api#deletemessage).

## Проверка реализации

Удаление выполняется под существующей блокировкой оператора с повторной
проверкой доступа. Потеря блокировки после первого удаления останавливает
второе. Связь сообщений остаётся для повторных попыток; старые связи из другой
темы или группы не подходят. Удаление не попадает в фоновую очередь, поэтому
отложенная очистка не обходит проверку прав оператора.

Журнал записывает подтверждённый результат атомарным запросом с проверкой
повтора. Повтор webhook после сбоя отправки подтверждения не дублирует
запись. Частичный результат и последующий успех учитываются отдельно.
Подтверждённое отсутствие уже удалённого сообщения не создаёт сигнал сбоя
Telegram или запись об ошибке в статистике.

Тесты проверяют успех, отсутствие копии, ошибки 400/403/429/503, неопределённый
результат, повтор webhook, альбом, замену темы и потерю блокировки. Для Free
и Paid проверяются все варианты от 0 до 44 оставшихся запросов D1, а также
продление блокировки во время медленного ответа Telegram. При исчерпании
бюджета webhook можно повторить, блокировки освобождаются.

Существующий общий счётчик ограничивает D1 значениями 50 запросов на Free и
1000 на Paid и сохраняет резерв для завершения обработки. Предупреждения
добавляются к существующим экранам без дополнительных запросов Telegram.
Нет нового polling, Cron или дополнительных сервисов; миграция не требуется.
Дневные квоты зависят от общего трафика всех функций; эти тесты проверяют
бюджет одного вызова, а не нагрузочную ёмкость всего аккаунта.

Актуальные лимиты проверены 13.10.2026:
[D1](https://developers.cloudflare.com/d1/platform/limits/),
[Workers](https://developers.cloudflare.com/workers/platform/limits/).
