# Повторная доставка по кнопке и подтверждение капчи

> Раздел установки ниже описывает прежний выпуск 0026–0027. Для текущего кода используйте [инструкцию Админушки](manager-bot.md) и [обновления БД](database-upgrade.md).

В личке Админушки откройте **Управление ботами поддержки → сервис → Проверка и восстановление доставки** для одного бота или **Контроль и восстановление → Восстановление доставки · все сервисы** для всех. Запуск начинается после подтверждения на экране без ожидания очередного Cron.

Запускать доставку и смотреть отчёт через эти экраны может только главный администратор в личном чате Админушки. Операторы и участники группы не могут запустить восстановление.

## Что показывает результат

- Время, область и состояние последнего запуска.
- Сколько шагов восстановления выполнено и сколько запросов отправки сделано.
- Сколько доставок из наблюдаемой очереди подтверждено за время запуска. Сюда может входить доставка, которую одновременно завершил Cron; служебные сообщения и исчезновение записи из очереди не считаются доставкой.
- Сколько сообщений осталось и почему они ожидают: капча, блокировка, ограничение, отключённый бот, неясный результат предыдущей отправки или необходимость получить исходное обновление от Telegram.
- Ответы об ошибках и время окончания ограничения Telegram, если оно мешало запуску.

**«Обновить результат»** только читает состояние. **«Попытка завершена»** означает завершение этого запуска, а не гарантированную доставку всей очереди. Если сообщения остались, можно сразу повторить запуск. Один запуск ограничен 12 шагами; при большом объёме очередь обрабатывается порциями. Список сообщений ограничен выборкой, знак `+` означает, что очередь больше показанного количества.

Если Worker аварийно остановился, в базе остаются состояние и последний сохранённый отчёт. Через две минуты такой запуск отображается как прерванный и перестаёт препятствовать новому. Отсутствие ответа или прерванный запуск не означают, что ни одно сообщение не было доставлено.

## Что защищает переписку

Используются те же механизмы, что в фоновой доставке: восстановление удалённой темы, сообщения при возобновлении обращения, альбомы и выпуск очереди после проверки или снятия ограничения. Блокировки отдельных пользователей и операций общие с Cron и webhook. Одновременно допускается один ручной запуск; повторные нажатия не создают параллельную отправку.

Кнопка не сбрасывает ограничения, капчу, идентификаторы уже обработанных сообщений и отметки о неясной отправке. Она не очищает историю. Во время полной очистки базы запуск запрещён; уже принятый запуск прекращается при изменении поколения данных.

Кнопка работает с сообщениями, уже сохранёнными приложением. Она не заставляет Telegram немедленно повторить ещё не переданное входящее обновление. Одиночную незавершённую отправку без исходного обновления нельзя безопасно восстановить во всех случаях: нужны личность оператора и параметры ответа. Такая запись показывается в отчёте, но не отправляется вслепую.

Если ограничен сам бот, которому принадлежит панель, он может не суметь показать результат до окончания ограничения. Сохранённый отчёт доступен после восстановления связи.

## Установка поверх уже выполненных 0024 и 0025

В этом обновлении добавляются две миграции:

- `0026_manual_delivery_runs.sql` — история последних 20 ручных запусков, блокировка параллельного запуска и индексы очередей.
- `0027_verification_notice_status.sql` — сохранение ID сообщения капчи и повторное обновление его статуса после успешной проверки.

Переписка и настройки сохраняются. Монитор, секреты, webhook и конфигурацию подключений менять не нужно. Выполняйте команды из папки проекта, по одному шагу; переходите дальше только после успешного завершения предыдущего.

1. Сделайте свежую резервную копию базы:

   ```powershell
   $deliveryBackup = Join-Path $env:TEMP ('telegram-support-before-manual-delivery-' + (Get-Date -Format 'yyyyMMdd-HHmmss') + '.sql')
   npx.cmd --yes wrangler@4.128.0 d1 export telegram-support --remote --config wrangler.toml --output "$deliveryBackup"
   if ($LASTEXITCODE -ne 0) { throw 'Экспорт не завершён. Следующий шаг пока не выполняйте.' }
   ```

   При ошибке авторизации `10000` выполните `npx.cmd --yes wrangler@4.128.0 login`, подтвердите доступ в браузере и повторите экспорт.

2. Примените миграции:

   ```powershell
   npx.cmd --yes wrangler@4.128.0 d1 migrations apply telegram-support --remote --config wrangler.toml
   ```

   Если последняя установленная миграция — 0025, ожидаются **`0026_manual_delivery_runs.sql` и `0027_verification_notice_status.sql`**. Подтвердите применение и дождитесь ✅ у обеих строк. Если 0026 уже применена, будет только 0027. Wrangler последовательно применяет все отсутствующие файлы; промежуточные deploy не нужны.

3. Опубликуйте основной Worker:

   ```powershell
   npx.cmd --yes wrangler@4.128.0 deploy --config wrangler.toml
   ```

4. В текущем интерфейсе откройте восстановление доставки через личку Админушки, как указано в начале документа. Для исторического выпуска 0026–0027 этот шаг выполнялся через `/menu` в General. Проверьте итоговый отчёт и сообщение в восстановленном топике; если отчёт не обновился, нажмите **«Обновить результат»**.

Внутренние этапы работают через приватный `ctx.exports.DeliveryRecovery`, без нового публичного HTTP-адреса или отдельного Worker. Каждый этап имеет собственный лимит запросов, а весь запуск ограничен по числу этапов и времени. [Документация Cloudflare](https://developers.cloudflare.com/workers/runtime-apis/context/).

## Как теперь выглядит успешная капча

После успешной проверки сайт показывает **«✅ Проверка пройдена»**. Сообщение с кнопкой в Telegram заменяется на **«✅ Проверка пройдена.»**, кнопка исчезает. Для английского языка используется соответствующий английский текст. Занятая очередь или ошибка доставки не заставляют проходить уже принятую проверку повторно и не означают, что сама проверка провалилась.

Если Telegram временно не позволяет отредактировать сообщение, бот повторяет редактирование в фоне. Это работает и после завершения доставки очереди. Повторный переход по ссылке не создаёт ещё одно подтверждение. Для обновления статуса используется приватный `ctx.exports.VerificationStatus` со своим лимитом запросов.

**Кнопка, отправленная старой версией:** прежний код не сохранял ID сообщения, поэтому автоматически отредактировать его нельзя. После обновления повторно откройте старую ссылку: если проверка остаётся действительной, сайт покажет успех, а бот один раз отправит подтверждение в чат. Старую кнопку можно удалить вручную. При развёртывании бот не рассылает подтверждения всем пользователям со старыми проверками.

Для проверки новой логики используйте следующую капчу, которую бот выдаст при обычном обращении: после прохождения должны измениться и страница, и сообщение в Telegram. Не нужно специально отправлять много сообщений или сбрасывать доверие основного аккаунта.
