# Архив: прежний мастер добавления ботов через Telegram

> Для текущего кода открывайте **Админушка → Управление ботами поддержки → Добавить сервисного бота** или `/addbot` в её личном чате. [Актуальная инструкция](MANAGER_BOT_SETUP_RU.md) описывает группы, проверку реакций и настройку алертов. Ниже сохранена история установки старого мастера; её шаги для General и версии миграций не следует применять к нынешней установке.

> Текущий набор миграций смотрите в [руководстве первого запуска](DEPLOY_FIRST_TIME_RU.md) и [настройке Админушки](MANAGER_BOT_SETUP_RU.md). Этот документ нужен только для понимания прежнего процесса и резервной копии `BOT_REGISTRY_KEY`.

После первоначального обновления подключение выполняется через **General → /menu → Боты → ➕ Добавить бота** или командой **/addbot**. Управление доступно только главному администратору. Мастер открывается в личном чате с существующим ботом поддержки.

Если бот уже подключён через файл настроек, повторно добавлять его не нужно. Боты из файла продолжают работать; новые записи хранятся в базе. Общие Worker, группа, база, капча и бот уведомлений используются всеми сервисами.

## 1. Однократное обновление работающей установки

Все команды выполняются в PowerShell из `C:\path\to\SupportDeskTg`. Этот раздел нужен один раз для установки функции. Для каждого следующего бота выполняйте только раздел 2 или 3.

### 1.1. Резервная копия

Экспорт временно делает базу недоступной для запросов. Дождитесь успешного завершения перед следующим шагом.

```powershell
$registryBackupDir = Join-Path $env:USERPROFILE '.codex\backups\telegram-support'
New-Item -ItemType Directory -Path $registryBackupDir -Force | Out-Null
$registryBackup = Join-Path $registryBackupDir ('before-bot-registration-' + (Get-Date -Format 'yyyyMMdd-HHmmss') + '.sql')
npx.cmd --yes wrangler@4.128.0 d1 export telegram-support --remote --config wrangler.toml --output "$registryBackup"
if ($LASTEXITCODE -ne 0) { throw 'Экспорт не завершён. Следующий шаг пока не выполняйте.' }
```

### 1.2. Обновление базы

```powershell
npx.cmd --yes wrangler@4.128.0 d1 migrations apply telegram-support --remote --config wrangler.toml
if ($LASTEXITCODE -ne 0) { throw 'Миграция не завершена. Следующий шаг пока не выполняйте.' }
```

Должна появиться ✅ у `0029_bot_registration.sql`. Если есть более ранние неприменённые миграции, команда выполнит их по порядку. Переписка и настройки сохраняются. База монитора не меняется.

### 1.3. Ключ для хранения токенов

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\initialize-bot-registry-key.ps1
if ($LASTEXITCODE -ne 0) { throw 'Ключ не настроен. Публикацию пока не выполняйте.' }
```

Скрипт создаёт случайный ключ и сам сохраняет его в секрет `BOT_REGISTRY_KEY` основного Worker. **Это не токен Telegram и не секрет капчи. Вводить или копировать ничего не требуется.** Ключ не выводится в консоль и не записывается в проект.

Локальная резервная копия защищена средствами Windows и сохраняется в `%USERPROFILE%\.codex\backups\telegram-support\telegram-private-chatbot-registry-key.dpapi`. Открыть её можно под тем же Windows-аккаунтом на этом компьютере. Для переноса на другой компьютер заранее сохраните сам ключ в своём менеджере паролей; одной копии `.dpapi` на другом компьютере недостаточно.

Если `BOT_REGISTRY_KEY` уже существует в Cloudflare, скрипт оставит его без изменений. Если загрузка прервалась, повторный запуск использует тот же сохранённый ключ. **Не заменяйте этот ключ случайным новым после добавления ботов:** старые токены зашифрованы прежним ключом. Резервная копия базы для полного восстановления требует и соответствующий ключ.

### 1.4. Публикация основного Worker

В текущем `wrangler.toml` уже добавлено `BOT_ONBOARDING_ENABLED = "true"`.

```powershell
node scripts/validate-wrangler.mjs
if ($LASTEXITCODE -ne 0) { throw 'Проверка настроек не пройдена.' }
npx.cmd --yes wrangler@4.128.0 deploy --config wrangler.toml
if ($LASTEXITCODE -ne 0) { throw 'Worker не опубликован.' }
```

**Если обновление уведомлений 0028 уже установлено и оба Worker опубликованы, монитор повторно публиковать не требуется.** При обновлении с более ранней версии сначала разверните монитор командой `npx.cmd --yes wrangler@4.128.0 deploy --config monitor/wrangler.toml`, затем основной Worker.

Теперь в General отправьте `/menu`, нажмите «Боты» и «➕ Добавить бота». Если Telegram предлагает кнопку Start в личном чате, нажмите её. Можно сразу отправить `/addbot` в личном чате с существующим ботом поддержки. Команды подключения и отмены также добавляются в личные подсказки главного администратора при синхронизации меню.

## 2. Подключить уже созданного бота

1. Откройте **General → /menu → Боты → ➕ Добавить бота**.
2. В личном чате выберите **«Подключить существующего»**.
3. Отправьте полный токен **добавляемого бота поддержки** из BotFather одним сообщением. Это не токен алерт-бота. Сообщение с токеном удаляется по возможности; в топик поддержки оно не пересылается.
4. Проверьте показанное `@имя_бота`. Перед добавлением в группу мастер предложит открыть **BotFather → /mybots → нужный бот → Bot Settings**: включите **Allow Groups** (`/setjoingroups` → **Enable**), выключите **Group Privacy** (`/setprivacy` → **Disable**, рекомендуемая настройка) и включите **Group Admin Rights → Manage Group**. Для перехода есть кнопка **«Открыть BotFather»**.
5. Нажмите **«Добавить в группу»**, выберите существующую группу «Поддержка» и выдайте права администратора: **управление темами и закрепление сообщений**. Если бот уже состоит в группе, проверьте его права в настройках группы. Group Admin Rights в BotFather задаёт предлагаемые права при добавлении, но не меняет действующие права в группе. Бот-администратор получает сообщения и при включённом Group Privacy; мастер не блокирует подключение только из-за этой настройки. Подробнее: [Telegram — Privacy Mode](https://core.telegram.org/bots/features#privacy-mode), [предлагаемые права администратора](https://core.telegram.org/bots/api#setmydefaultadministratorrights).
6. Вернитесь в мастер и нажмите **«Проверить подключение»**. Он проверяет именно настроенную группу поддержки, а не любую выбранную группу.
7. Введите название сервиса и короткий префикс топиков. Например, `Мой магазин` и `SHOP`. Можно использовать предложенные кнопки.
8. Проверьте итоговую карточку и нажмите **«Подключить»**.
9. Дождитесь **«✅ @… подключён»**. Сообщения Telegram теперь направляются в существующий Worker. Отдельные секреты, миграция и deploy для этого бота не нужны.
10. В General появится напоминание настроить тексты. Откройте `/messages`, выберите нового бота и отдельно задайте приветствие и подтверждение получения обращения. По умолчанию оба выключены; их можно оставить пустыми.

Если у бота уже есть другое подключение, карточка покажет его домен и кнопку **«Переключить и подключить»**. Нажимайте её, только если хотите перенести этого бота в текущую поддержку: прежняя система перестанет получать его новые сообщения. Если подключение изменилось после показа карточки, потребуется повторное подтверждение.

## 3. Создать нового бота непосредственно кнопкой

1. Один раз откройте **мини-приложение BotFather**, выберите существующего бота, через которого запускаете мастер, и включите **Bot Management Mode**. В вашей установке это обычно `@example_support_bot`. Отдельного бота-менеджера создавать не требуется.
2. Откройте мастер `/addbot` и выберите **«Создать нового»**.
3. Нажмите появившуюся кнопку **«Создать бота поддержки»**. В окне Telegram задайте имя и свободный username, заканчивающийся на `bot`, и подтвердите создание.
4. Вернитесь в личный чат мастера. Токен будет получен автоматически. Дальше добавьте бота в группу, проверьте права и задайте сервис и префикс, как в разделе 2.
5. При подтверждении подключения созданный бот становится доступен пользователям, чтобы они могли писать в поддержку.

При запуске создания мастер сам включает получение служебных событий управления ботами, сохраняя очередь Telegram. Если режим в BotFather выключен, мастер объяснит, что включить. Если ваш клиент Telegram не показывает окно создания, обновите его либо используйте подключение по токену.

Официальное описание: [Telegram — Managed Bots](https://core.telegram.org/bots/features#managed-bots), [кнопка создания](https://core.telegram.org/bots/api#keyboardbuttonrequestmanagedbot).

## 4. Проверка после подключения

1. Со второго аккаунта отправьте **обычное текстовое сообщение** новому боту. Один `/start` может показать только приветствие и не создавать обращение.
2. В группе должна появиться тема с выбранным префиксом и сообщением пользователя.
3. Ответьте в этой теме. Ответ должен прийти пользователю от нового бота.
4. В General откройте `/bots`: новый сервис должен присутствовать в списке.

Капча и ограничения продолжают работать. При запросе проверки сначала пройдите капчу. По умолчанию никаких новых приветствий, подтверждений или пользовательских кнопок, кроме необходимой капчи, не добавляется.

## 5. Если что-то прервалось

| Ситуация | Что делать |
| --- | --- |
| Не хватает прав в группе | Выдать управление темами и закрепление сообщений; снова нажать «Проверить подключение». |
| Telegram не подтвердил подключение | Нажать «Повторить подключение». Используются тот же адрес и секрет; очередь Telegram не очищается. До завершения сообщения могут оставаться в очереди Telegram, срок её хранения ограничен Telegram. |
| Токен перевыпущен в BotFather | Для обычного бота снова открыть `/addbot` → «Подключить существующего» и ввести новый токен того же бота. Для незавершённого подключения есть «Ввести обновлённый токен». |
| Токен созданного через мастер бота изменён | При получении служебного события он обновляется автоматически. При смене владельца подключение приостанавливается и требует проверки главным администратором. |
| Нужно закрыть мастер | Нажать «Отмена» / «Закрыть мастер» или отправить `/cancel`. Существующие подключения не удаляются. Начатое подключение можно возобновить тем же токеном. |
| Настройка устарела | Открыть `/addbot` заново. Черновик до подключения хранится один час; начатое подключение сохраняется до продолжения или закрытия мастера. |
| Этот бот уже подключён через файл | Повторное добавление не нужно. Его токен пока обновляется через существующий секрет Cloudflare. |

Повторное подключение бота из меню сохраняет его внутренний ID, историю, тексты и секрет доставки. Удаление истории через «Хранилище» не удаляет подключения и ключ. Мастер поддерживает до 50 добавленных через меню ботов.

## Проверки разработки

`node --test test/bot-registration.test.js` проверяет шифрование, права, этапы мастера, повторы, смену подключения и управляемых ботов. Интеграционные тесты `registered bot:` в `test/support-worker.test.js` проверяют обычную доставку, ответ оператора, General, Cron, ручную доставку и капчу с реальным обработчиком при лимите запросов Free. `npm.cmd test` запускает весь набор; `node scripts/validate-wrangler.mjs` проверяет сборку обоих Worker.

Отдельно проверены восстановление ключа после сбоя загрузки (Cloudflare заменён тестовой заглушкой) и локальная связка workerd: HTTP-мастер → шифрованная запись D1 → напоминание в General → доставка нового пользователя → RPC мониторинга и ручной доставки. Эти проверки не создают настоящих ботов и не подтверждают результат на реальном аккаунте Telegram: после установки выполните проверку из раздела 4.
